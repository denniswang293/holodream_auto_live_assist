# V7.13.1 Global ETA Guard Findings

日期：2026-11-02

## 修補結論

已修正 Global ETA 不確定度被 `min(..., max_uncertainty_s)` 事先封頂的安全錯誤。現在會保留未截斷的不確定度，超過上限時回傳 `REJECTED / eta_uncertainty_too_high`，因此不會產生 Global proposal。

Global ETA 仍維持 Shadow；`config/live_assist.json` 沒有改成 Active，`allow_active` 仍為 `false`。

## 修補內容

### `src/global_tap_timing.py`

- 新增 `velocity_sigma_px_s`，由跨 Track MAD 與同 Track 斜率波動組成。
- 使用有量綱的一階誤差傳播：

  ```text
  sigma_t = sqrt((sigma_y / v)^2 +
                 (abs(distance) * sigma_v / v^2)^2)
  ```

- 不再把速度相對誤差直接當成秒，也不在 gate 前封頂。
- 非有限輸入、速度無效、歷史失效與不可靠模型不會產生有效 ETA。
- `global_tap_timing_shadow.csv` 保留實際超標 uncertainty。

### `src/simple_core.py` / `src/tap_planner.py`

- Global proposal 仍只在 `status=AVAILABLE` 且 uncertainty 通過 gate 時產生。
- Active 分支即使雙開，也只能替換已經通過 Legacy/PF 全部品質 gate 的 proposal；不能用 Global ETA 繞過 PF observation-quality gate。
- Shadow 不呼叫第二次 `Scheduler.offer`，不改原 PF proposal、key、deadline 或 Hold reservation。

### 測試

新增測試涵蓋：

- 大速度離散、遠距離與高位置誤差造成 uncertainty 超過 40ms 並被拒絕。
- 穩定速度、小誤差仍可 `AVAILABLE`。
- ETA 距離增加時，速度誤差造成的時間不確定度不會反常縮小。
- NaN/Inf、零速度、非規則 timestamp、stale/coasting。
- Global Planner 不排程超標 ETA。
- Shadow actuator 呼叫為零。
- Active 雙開仍不能繞過 PF gate。
- 既有 Hold、Scheduler、失焦／停用／ESC/F12 與改鍵安全測試。

## 修補前後安全案例

| 案例 | 修補前 | 修補後 |
|---|---|---|
| `uncertainty_raw > 40ms` | 先被截成 40ms，可能回傳 `AVAILABLE` | 保留真值，回傳 `REJECTED / eta_uncertainty_too_high` |
| 速度誤差項 | 將無量綱 `MAD / v` 混入秒數 | 使用 `distance * sigma_v / v²` |
| Global proposal | 可能使用被封頂的 ETA | 超標 ETA 不會進入 proposal |
| Active 分支 | 理論上可能繞過 PF gate | 只替換已通過 Legacy/PF 的 proposal |
| Shadow | 不應影響輸入 | MockActuator 呼叫維持 0，並有回歸測試 |

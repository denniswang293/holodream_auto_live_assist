# 人工標註計畫

`holodream.json` 目前只有影片身分與三個待審區間，**沒有人工真值**。`holodream.csv` 是空白匯出格式。不要將 v2/v3 候選、track ID 或時機預測直接複製成 confirmed 真值。

先啟動 `python -m tools.annotate --video holodream.mp4`。三個初始區間位於 11s、22.8s、54s 附近，`complete=false`；可在介面擴充區間。目標是至少 30–50 筆跨場景音符，另有背景負樣本。

| 情境 | 建議筆數／檢查 |
|---|---|
| 一般 tap | 約 10 筆，包含灰白條 |
| 同時音符 | 約 8 筆；每顆獨立 ID，不把一個寬條切成 chord |
| 寬條 | 約 6 筆；記可見位置範圍，實際輸入鍵未知則空白 |
| Hold 起／終 | 約 8 筆；看不清真實判定時維持 uncertain |
| Slide | 約 6 筆，記短間隔軌跡觀測 |
| Flick | 約 8 筆；只有粉色並不足以確認類型或鍵位 |
| 背景光效負樣本 | 另約 6 筆，包含底部亮條、角色／技能文字、路徑碎片；需點選 u、v 與影格區間 |

這是取樣目標，不是已存在的 46 筆真值；場景可能重疊，最後以實際人工確認數為準。

逐幀前後核對後指定 frame_hit、hit_reference（前緣／中心／判定特效）與 reviewer；時機或類型不能確認時選 uncertain。`verified_keys` 只有在遊戲規則及實際輸入已證實時才填，不由圖上幾何 lane 推導。

若要量測追蹤碎片，在同一 manual ID 的不同影格點選主體中心並加入軌跡，建議間隔 ≤6 幀。這些點只作短距離內插與 ID 追蹤診斷，不代替人工判定幀。

只有區間內所有真實音符已標齊時才勾選 complete。未標完整的區間不會把未配對事件計成一般 FP。背景負樣本只在來源幀、u 範圍與 v（容許約 8px）一致時作局部負證據；不將整條 lane 都視為背景。

評估至少需要 30 個 complete 區間中的 confirmed 音符；時間 MAE/P95 與已解析鍵位正確率各自需要至少 30 組可比較配對。不足時會輸出未評估，仍保存逐項診斷以供核對。

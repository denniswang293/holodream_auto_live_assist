# HoloDream V7.14.2 implementation result

日期：2026-11-02

## 完成項目

### P0：物理穿越線與 press deadline 分離

- `GlobalTapTimingEstimator` 現在可分開輸出：
  - `physical_cross_at`：音符中心預測穿越 `geometry.hit_y=325.5` 的時間。
  - `press_at` / `hit_at`：實際送鍵 deadline。
  - `lead_ms`：唯一明示的輸入提前補償。
- `config/live_assist.json` 使用 `timing_reference=physical_calibrated`，目前 `input_lead_ms=0.0`，避免在沒有 FAST/SLOW 真值時偷偷沿用或重複扣除 30px 提前量。
- `tap_deadline_amend.allow_earlier_amend=false`：模型更新不會反覆把既有 deadline 向前推；原有 freeze、單步與總幅度限制保留。
- `tap_intents.csv`、`live_events.csv`、`global_tap_timing_shadow.csv` 增加 timing source、physical crossing、press、lead、speed epoch 與 timing group 欄位。

### P1：每曲 Global profile 與速度 epoch

- y-profile 仍只使用當前 session 的真實 matched observation。
- 同一 UID 的同一 `(t0,t1,segment)` observation pair 只會入庫一次，避免每幀重複加權。
- profile 在 PLAYING 邊界、失焦／停止 invalidation、Arm generation 變更時 reset，並記錄 `speed_epoch`、`calibration_state`、`profile_age`。
- sparse segment 使用 bounded uncertainty penalty；資料不足仍會 `NOT_READY`，沒有跨曲固定速度或 PF/Linear ETA fallback。

### P2：混合和弦

- Global Planner 對不同 UID、不同合法鍵、physical crossing corridor 內的 Tap 標記 `timing_group_id`。
- 每個 UID 仍各自建立 Intent，Scheduler 的 key reservation、Hold 保護、失焦與 emergency release 不變；group metadata 不是繞過 reservation 的旁路。
- Hold head 在 physical-calibrated 模式使用其 physical head crossing 減去同一個明示 lead；尾端仍由視覺 Hold tracker 控制放鍵。

### 離線工具

- `tools/calibrate_v7142_timing.py`：以 capture timestamp、實際 track bbox 與 key action 比較 0/30/60/90ms lead。若 tracker 在 physical line 前結束，使用 bounded last-segment extrapolation 並明確標記 proxy。
- `tools/analyze_v7142_song_timing.py`：產生兩個既有 run 的 paired lifecycle/timing summary。

## 實機測試方式

1. 固定同一首歌、難度、視窗和錄影設定，先用目前 `input_lead_ms=0` 跑 20–40 秒。
2. 錄影選 `Y`，保留 `live_run.json`、`global_tap_timing_shadow.csv`、`tap_intents.csv`、`input_actions.csv`、`live_video_index.csv`。
3. 由使用者觀察並記錄逐顆 FAST/SLOW/MISS；不要把 Assist 的 `FIRED` 當成遊戲判定。
4. 再只改 `input_lead_ms` 為 30、60、90 其中一個值重跑同一首歌，使用校準工具比較。
5. 若需回退 V7.14.1 時序，將 `global_tap_timing.timing_reference` 改為 `trigger_legacy`；這是設定回退，不會啟用 PF/Linear ETA。

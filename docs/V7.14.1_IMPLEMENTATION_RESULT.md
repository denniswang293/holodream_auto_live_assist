# V7.14.1 Global ETA recovery implementation result

日期：2026-11-02

## 結論

已完成 Global-only ETA 的兩個主要修正：

1. Global 模型由不同高度共用單一像素速度，改為有限 4 段的共用 `v(y)` profile，使用同一批實際 matched observation 的 capture timestamp 建模與積分 ETA。
2. SimpleTracker 增加窄範圍的 late-entry early confirmation：至少 3 次獨立 matched observation、單調前進、穩定合法鍵、無 overlap/path/競爭，且只在接近 trigger 時啟用。

PF 仍是 tracking-only；普通 Tap 的 ETA、`hit_at`、proposal deadline 仍只由 GlobalTapTimingEstimator 提供。沒有 PF/Linear ETA fallback。Hold、30px 提前目標、Scheduler freeze、Arm/focus/stale/ESC/F12 安全條件維持。

## 修改檔案

- `src/global_tap_timing.py`
  - 新增 bounded y-profile、segment robust median/MAD、profile TTL、profile source、profile age、單軌 bootstrap。
  - ETA 使用 `integral(1/v(y) dy)`，再加上最後實際觀測的 capture timestamp。
  - 缺段時只能使用最近已驗證區段並增加 uncertainty；資料不足仍 `NOT_READY`。
  - 速度變化在同區段且多軌證據不可靠時回傳 `speed_variation_too_high`，不同高度不再互相直接否決。
- `src/simple_tracker.py`
  - 新增 `tracking_velocity`，確認與空間 association 不再依賴 PF hit-time。
  - 新增 `early_near_trigger` confirmation，並記錄首次觀測／首次確認 y、timestamp、確認模式及是否已過 trigger。
  - 放寬的是單一、可驗證的 late-entry association tolerance，不是全域降低 confirmation gate。
- `src/simple_core.py`
  - Global Active 使用 profile ETA 直接建立 proposal；Global 不可用時不回退 PF/Linear。
  - Global Shadow 不呼叫 Scheduler，並保留 model source/profile segment/age 診斷。
  - 记录 READY coverage、拒絕原因與每個 UID 首次排程時間；失焦、停止、切換 Arm generation 時清除 Global profile。
- `src/live_identity_trace.py`
  - `live_track_identity.csv` 增加 early confirmation evidence 欄位。
- `src/live.py` / `src/live_engine.py`
  - `live_run.json`、`run_metrics.json`、事件記錄標示 Global timing source。
- `config/live_assist.json`
  - 維持 `global_tap_timing.enabled=true`, `mode=active`, `allow_active=true`；`linear_timing.enabled=false`。
- `tools/analyze_v7141_global_recovery.py`
  - 新增可重跑的 capture-time UID hold-out baseline/profile 比較工具，不讀 PF ETA、不使用未來影格預測過去、不送鍵。
- `tests/test_global_tap_timing.py`、`tests/test_simple_core.py`
  - 新增 y-dependent profile、單軌 bootstrap、late-entry fixture、PF NaN/Inf 隔離與 Global-only 回歸測試。

## 對 late-confirm 與未排程 UID 的處理

- 對首次可信觀測已接近 trigger 的音符，early confirmation 可以讓 Global 在仍有正 ETA 時建立 proposal。
- 若首次可信確認已經超過 trigger 或 Global uncertainty/horizon 不通過，仍會 `NOT_SCHEDULED`，不做過期補按。
- `model_not_ready`、`confirmed_too_late`、`uncertainty_rejected`、`key_conflict`、`already_pending/fired` 維持分開；未觀測到的真實音符不會被標成 MISS。

## 實機驗收與已知風險

V7.14.1 尚未由 Codex 啟動 WindowsActuator。請使用者手動執行 `tools/launch_assist.cmd`，同一首歌前 40–50 秒錄影選 Y，保留 `live_run.json`、`run_metrics.json`、`global_tap_timing_shadow.csv`、`tap_intents.csv`、`input_actions.csv`、`live_video_index.csv` 與 `live_source.mp4`。

目前最大風險是 Global profile 在資料稀疏、速度 regime 改變或跨段外推時會 fail-closed，造成尚未排程；這是安全的 `NOT_READY`，不是理由去放寬 uncertainty、lateness 或切回 PF ETA。真實遊戲準確度目前仍為 `UNKNOWN`。

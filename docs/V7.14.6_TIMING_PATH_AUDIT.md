# V7.14.6 Tap timing path audit

This audit follows the active Assist path in the workspace and the recorded
run `output/run_20261102T170607_698182Z`. It is diagnostic only. No active
geometry, lead, Planner, Scheduler, Hold, focus, stale-frame, or safety gate
was relaxed.

## Data flow

```text
capture timestamped frame
        |
        v
normalization -> detector Candidate.bbox=(x,y,w,h)
        |
        v
SimpleTracker: center y+h/2 + timestamped history
        |
        +--> Particle Filter track state (tracking-only)
        |
        v
GlobalTapTimingEstimator
  profile from capture-time history -> physical crossing at geometry.hit_y
  press_at = physical_cross_at - input_lead_ms
        |
        v
Legacy Tap Planner gates/key assignment
        |
        v
TapIntentManager deadline amendment (bounded/freeze/earlier guard)
        |
        v
TapScheduler -> input action log / Win32 actuator
```

Hold uses the separate visual-tail path. The V7.14.6 tool only replays Tap
geometry hypotheses and never calls the actuator.

## Coordinate meanings and source

- Detector produces the candidate rectangle and appearance in `src/detector.py`
  (`detect`, final candidate post-processing around lines 117–400). The stored
  rectangle is in the normalized 720×404 reference space for this run. Effects,
  clipping and path fragments can change its height; the tool therefore marks
  uncertain rows `UNRELIABLE_BBOX`.
- `src/simple_tracker.py` defines `_center` as `y + h/2` (around line 142),
  writes `(capture_timestamp, center_y, lane_center)` to `history` (around
  line 262), and uses that center for ordinary Tap tracking. It does not use
  the bottom edge in the active path.
- `src/live_engine.py` loads `config/geometry_live_assist.json` through
  `load_calibration` and sets `input_advance_px` (around lines 183–196). The
  run records `tracking_completion_y=325.5` and `input_trigger_y=295.5`, so the
  active timing target is the calibrated Live Assist geometry, not the legacy
  `config.json.playfield.hit_y=352` field.
- The calibration snapshot in this run is `status=pending_calibration` and
  `AUTO_ESTIMATE_NOT_MANUAL_VALIDATION`; its hit line is an unverified
  machine-derived native-frame estimate. This is evidence about what ran, not
  proof that the game's judgment line is at that y.
- `src/global_tap_timing.py` updates the shared profile using capture
  timestamps (around lines 190–335). `estimate` (around line 424) uses the
  last effective observation and computes the physical crossing, then subtracts
  the configured lead to form `press_at`. `src/simple_core.py` passes
  `physical_hit_y=geometry.hit_y` only when the physical-calibrated mode is
  active.
- `src/tap_planner.py` retains the Legacy decision gates and key legality.
  `src/tap_intent.py` receives the nested `tap_deadline_amend` settings and
  applies step, total, freeze-window and `allow_earlier_amend` checks (lines
  48–145). `src/live_input.py` rejects amended deadlines in the freeze window
  or in the past (around lines 272–296).

## Run evidence

The run contains 162 UIDs with usable real observations, 105 Tap key-down
rows, 213 amendment actions over 80 UIDs, 173 dropped capture frames and
processing FPS 61.10 versus capture FPS 64.21. The run's numeric
`input_lead_ms` is 60.0, but its copied labels say `V7.14.3-lead-10ms`.
This label mismatch is a confirmed diagnostics defect; it does not change the
numeric timing used by the engine. New runs now derive the label from the
numeric lead in memory.

The legacy `press_time_not_future` count (87 model estimates in `live_run.json`)
is an estimate/gate count, not 87 game misses. No game-grade truth is present.

## What remains unproven

The current run can compare top/center/bottom visual crossings and nearby y/lead
hypotheses, but it cannot determine the game's true anchor or judgment line.
The source video and same-run video index provide timestamp alignment, yet no
one-to-one per-UID grade labels. A `key_down`, `FIRED`, note disappearance or
overlay word is therefore not used as PERFECT/GREAT/SLOW truth.

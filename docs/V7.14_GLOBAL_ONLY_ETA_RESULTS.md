# V7.14 Global-only ETA / PF tracking-only 實作結果

日期：2026-11-02

## 最終資料流

普通 Tap 現在採用：

```text
Detector → SimpleTracker（每顆 UID、位置、lane、觀測歷史）
         → PF tracking-only（空間關聯、位置/速度、ESS、量測品質）
         → GlobalTapTimingEstimator（唯一 ETA / hit_at）
         → TapPlanner → TapIntentManager → TapScheduler
```

Hold 仍走既有視覺尾端放鍵路徑；30px 提前目標、`hit_y=325.5`、`trigger_y=295.5`、Arm/focus/stale/ESC/F12 安全條件未修改。

## 主要修改

- `src/particle_predictor.py`
  - SimpleTracker 建立 PF 時使用 `timing_enabled=False`。
  - PF 仍提供位置、速度、ESS、觀測品質與 spatial association；Simple Tap 不再從 PF 取得可消費的 ETA/hit_at。
- `src/simple_tracker.py`
  - 新增獨立 `tracking_velocity`，供空間 matching/confirmation 使用。
  - 移除 Simple Tap confirmation、association 對 PF hit-time 的依賴。
  - `SimpleTrack.eta()` 不再暴露 PF Tap ETA。
- `src/global_tap_timing.py`
  - 支援單一音符的多次高品質觀測冷啟動；後續仍以實際 track 更新。
  - 固定速度不可靠、速度 regime 變化、coasting、stale、跳點與非數值資料會 fail-closed。
  - uncertainty 使用位置／速度誤差傳播，不提前封頂。
- `src/simple_core.py`
  - Global Active 時直接由 Global proposal 建立 Tap intent，不再先經 PF timing planner 再覆蓋。
  - Global 無法使用時只記錄 `NOT_SCHEDULED` 原因，不回退 PF、Linear 或舊 ETA。
  - 每個 UID 記錄首次 Global schedule 時間、READY coverage 與拒絕原因。
- `src/tap_planner.py`
  - Global planner 只使用確認狀態、最新位置、lane/合法鍵、Global ETA/uncertainty 與 Scheduler reservation。
  - 多合法鍵會依覆蓋程度嘗試下一個不衝突鍵；Hold/同鍵/35ms conflict window 維持原安全規則。
- `src/live_engine.py` / `src/live.py`
  - 普通 Tap 事件的 `predicted_hit_time`、uncertainty 與 predictor source 改為 Global。
  - `live_run.json`、`live_diagnostics.md`、`run_metrics.json` 增加 `tap_timing_source=global` 與 Global READY/拒絕統計。
- `config/live_assist.json`
  - `global_tap_timing.enabled=true`
  - `mode="active"`
  - `allow_active=true`
  - Global 無法驗證時拒絕送鍵，不暗中回退 PF。
- `README.md`、`tools/launch_assist.cmd`
  - 改為說明 Global Fixed-Speed ETA 是 Tap 唯一時間來源，PF 只做追蹤。

## 實機驗收與風險

Codex 沒有啟動 WindowsActuator，也沒有替使用者送鍵。請手動執行 `tools/launch_assist.cmd`，錄影選 `Y`，保持目前 Global Active 設定，測試 30–60 秒；若模型大量 `NOT_READY`，系統會安全 abstain，而不是回退 PF。

新 run 至少保留：

- `global_tap_timing_shadow.csv`
- `tap_eta_comparison.csv`
- `tap_intents.csv`、`input_actions.csv`
- `live_run.json`、`run_metrics.json`、`live_video_index.csv`
- `live_source.mp4`（不要放進 Git）

沒有獨立遊戲判定真值時，`FIRED`、`key_down`、UID 數量只能代表軟體動作，不代表遊戲 HIT；報告應標為 `UNKNOWN`。若 Global READY coverage 不足，下一輪只調查有證據的共用速度/位置映射，不得偷偷切回 PF timing fallback 或放寬安全門檻。

## 回復設定

若需停用 Global 輸入，將 `global_tap_timing.enabled=false` 或 `mode="shadow"`；這會 fail-closed，不會恢復 PF Tap ETA fallback。回復前應保留 run 的 CSV 與影片供分析。

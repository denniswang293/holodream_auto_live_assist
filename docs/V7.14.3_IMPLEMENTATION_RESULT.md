# HoloDream V7.14.3 implementation result

日期：2026-11-03

## 修改

### P0：Global profile uncertainty

- 移除 physical-calibrated ETA 中以整段距離乘上全域 `velocity_sigma / velocity` 的舊誤差項。
- `_profile_eta()` 現在只累積各高度區段自己的速度殘差、缺段外推與 sparse penalty。
- 目前位置的 `measurement_noise_px` 改用該位置附近的 local `v(y)`，不再用整條軌道 median velocity。
- 保留 bounded process floor，避免 profile sigma=0 被視為完美精度；同區段速度離散過大仍 fail closed。
- `max_uncertainty_s=0.04`、physical line、合法鍵、Hold reservation、focus/stale/Arm/ESC/F12 均未放寬。

### P1：模型可用時機

- 保留 `GlobalTapTimingEstimator` 的 profile TTL、speed epoch、pair 去重與 physical target coverage。
- ETA 超過 `.45s` 仍只追蹤與準備，不建立 Scheduler intent；進入窗口後才可排程。
- pending/frozen intent 仍由 TapIntentManager/Scheduler 擁有，不因暫時 dropout 重新建立 UID。

### P2：MISS 分類工具

- `tools/analyze_v7143_miss_replay.py` 使用同一份 run 的 capture timestamp、video index、identity、Global CSV、Tap lifecycle 與 input actions。
- 產出逐 UID before/after 表，以及三個影片 MISS 時間窗的同步動作摘要。
- 未有逐顆遊戲判定標註時分類保持 `UNRESOLVED`／`UNKNOWN`，不把 key_down 或 FIRED 當 HIT。

## 實機驗收

請使用者以同一首歌、同一設定跑 30–60 秒，保留：

`live_source.mp4`、`live_video_index.csv`、`global_tap_timing_shadow.csv`、`tap_intents.csv`、`input_actions.csv`、`live_run.json`。

人工記錄每顆遊戲 `MISS/FAST/SLOW` 與實際按鍵，並與 UID 對照。沒有遊戲真值前，準確率保持 `UNVERIFIED`。不要先調大 40ms uncertainty、max lateness 或 lead。

# V7.14.8 source-first run instructions

The normal launcher no longer needs `config.json` or
`config/live_assist.json` for basic Assist behavior. It still requires the
external calibrated geometry file; geometry is not hard-coded because its
manual validation is pending.

Candidate profile (the current user-preferred experiment; visibly marked
experimental at startup):

```powershell
python -m src.live --profile tap-earlier --geometry config/geometry_live_assist.json --record-overlay --out output/assist/v7148_experiment
```

Stable rollback profile:

```powershell
python -m src.live --profile stable --geometry config/geometry_live_assist.json --record-overlay --out output/assist/v7148_baseline
```

Both profiles use 60ms lead and all existing limits. They differ only in
`live.tap_deadline_amend.allow_earlier_amend`. Input starts OFF; manually arm
with `Ctrl+Shift+Alt+Q`, and use Esc/F12 to stop and release keys. Do not run
both at once.

## Explicit legacy overrides

The old path remains available when explicitly requested:

```powershell
python -m src.live --profile stable --config config.json --live-config config/live_assist.json --geometry config/geometry_live_assist.json --out output/assist
```

The run is labelled `legacy_override`; nested merges preserve freeze, step,
total, lateness, uncertainty and stale-frame limits. Invalid geometry, key
mapping or safety values fail closed rather than silently falling back.

## A/B evaluation

After running the same song segment A → B → B → A, manually review the
generated `tap_game_grade_review.csv` files and retain UNKNOWN for any
non-one-to-one case. Then compare:

```powershell
python tools/compare_v7147_ab.py --baseline output/assist/v7148_baseline/<run_A> --experiment output/assist/v7148_experiment/<run_B> --out-dir output/analysis_v7148
```

At least 30 trusted Tap grades per group are required before SLOW/MISS/FAST
rates can be compared. Otherwise the report remains
`INSUFFICIENT_GROUND_TRUTH`.
